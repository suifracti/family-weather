# D2.3d1 COS 发布适配

本轮只增加“已有标准字幕产物 → COS 广州默认 HTTPS 域名”的发布边界。它不改变 manifest v1、exact episode 身份、Android 配置入口、天气逻辑或 ASR 模型，也不把 GitHub Pages 删除或切换成 Android 生产源。

## 实现边界

`tools/asr/publishing.py` 提供两个目标：

- `LocalStaticPublisher`：只校验/整理本地静态目录，不导入 COS SDK、不访问网络、不读取 COS 凭据。
- `TencentCosPublisher`：只接收已经存在的标准产物；本地校验通过后，用锁定的 `cos-python-sdk-v5==1.9.44` 签名 `PutObject`，再用不带鉴权的公开 HTTPS `GET` 做回读验证。该 SDK 版本的公开 `put_object` 参数映射没有暴露 `x-cos-forbid-overwrite`，日期对象因此沿用 SDK 自己的 `CosS3Auth + send_request` 签名路径显式发送该官方请求头；不把一个生产 SDK 不认识的伪参数传给真实客户端。COS SDK 在目标真正创建时才延迟导入，ASR 核心和本地模式不依赖它。

`DailySubtitlePublisher.run(..., remote_publisher=...)` 仍分别返回 `localPublishStatus` 与 `remotePublishStatus`。即使本地产物命中 `NO_OP / ALREADY_PUBLISHED`，也会调用远端目标，因此首次补传和上次失败后的重试不会被提前返回跳过。

## 固定对象路径与验证顺序

对象键固定为：

```text
subtitles/evening-weather/index.json
subtitles/evening-weather/YYYY-MM-DD/manifest.json
subtitles/evening-weather/YYYY-MM-DD/subtitle.vtt
```

默认公开 URL 使用 virtual-hosted HTTPS：

```text
https://<Bucket-Appid>.cos.<Region>.myqcloud.com/<object-key>
```

不会把 `subtitles/` 再拼接一次，也不会使用 path-style `cos.<Region>.myqcloud.com/<Bucket-Appid>`。

发布一日时严格执行：

1. 读取已有 `manifest.json` 和 `subtitle.vtt`。
2. 用现有 v1 JSON Schema 校验 manifest，校验目录日期与 `manifest.episodeDate` 一致，并校验 VTT `WEBVTT` 头和 `vttSha256`。
3. 先补传/验证 VTT，再补传/验证 manifest。回读使用无鉴权 HTTPS GET，检查最终响应状态、实际 `Content-Type`、实际 `Content-Disposition`、字节内容和 SHA-256；新上传的 manifest 要求字节/hash 精确相同，已有 manifest 按 v1 schema 的全部字段语义比较（包括 `cueCount`、`sourceVideoUrl`、`durationMs`、`generatedAt`、ASR 字段等），签名 GET 不算通过。
4. 只有该 exact date 的两个对象已经通过公开 GET，才上传 `index.json`，并再次公开 GET 校验 index 的字节、JSON 和 exact manifest 引用。

日期产物使用 `public, max-age=31536000, immutable`；index 使用 `no-cache, max-age=60`。上传请求显式设置 `application/json; charset=utf-8`、`text/vtt; charset=utf-8` 和 `Content-Disposition: inline`。回读报告的是服务最终响应头，不把请求元数据冒充成最终结果。新桶默认域名可能仍返回 `Content-Disposition: attachment`；这只表示浏览器下载策略，不能替代或否定 Android 对 JSON/VTT 正文的公开 GET 验证。

上传顺序不是跨对象原子事务。Android 按 exact date 直接取 manifest，不依赖 index 隔离；在 VTT/manifest/index 依次上传的窗口内，外部读取可能看到不完整日期，因此发布器在 index 前拒绝继续提交。日期对象的 PUT 使用服务端 `x-cos-forbid-overwrite=true`；初始 GET 404 后若发生 409/FileAlreadyExists，会再次公开读取，同内容才按幂等成功处理，不同字节/字段返回 `REVISION_CONFLICT`，不会继续提交 index。index 是可更新对象，不使用禁止覆盖头；发布器在写 index 前重读并验证已有较新指针，旧日期补传不会回退 latest。当前边界是单发布者：index 最后一次公开 GET 之后仍可能有另一个 index 写者竞争，下一轮需人工/调度层协调，不把这段顺序描述为 CAS 或多对象事务。若中途失败，重跑同一标准产物可补齐相同内容；若同日已有完整但不同 `sourceVideoSha256`、VTT hash 或任意 manifest v1 字段，则返回 `REVISION_CONFLICT`，本轮不自动删除或覆盖。恢复方式是保留原完整日期并人工确认后另行处理，不能靠改 index 隐藏冲突。

## 可重复命令

本地校验/整理已有产物，不需要 COS 依赖或任何凭据：

```powershell
python -m tools.asr.publisher `
  --publish-existing `
  --episode-date 2026-09-17 `
  --output-dir dist/subtitles/evening-weather `
  --publish-target local
```

COS 目标只读取本机环境变量。不要把 Secret 发到聊天、写进仓库、`local.properties`、Kotlin、BuildConfig 或 APK：

```powershell
$env:TENCENT_CLOUD_SECRET_ID = '<本机安全存储中的 SecretId>'
$env:TENCENT_CLOUD_SECRET_KEY = '<本机安全存储中的 SecretKey>'
$env:TENCENT_COS_REGION = 'ap-guangzhou'
$env:TENCENT_COS_BUCKET = '<BucketName-Appid>'
# 临时凭据可额外设置下列之一；不使用临时凭据时不要设置。
$env:TENCENT_CLOUD_SESSION_TOKEN = '<本机安全存储中的 Token>'

python -m pip install -r tools/asr/requirements-cos.txt
python -m tools.asr.publisher `
  --publish-existing `
  --episode-date 2026-09-17 `
  --output-dir dist/subtitles/evening-weather `
  --publish-target cos `
  --report-file release/cos-2026-09-17-report.json
```

也接受 `TENCENT_CLOUD_TOKEN` 或 `TENCENTCLOUD_SESSION_TOKEN` 作为临时 token 环境变量别名。成功时 stdout 和 `--report-file` 都给出安全结构化证据：local/remote 状态、三个公开 URL、最终 GET 响应头、对象键、验证键和 SHA-256；请求元数据仍单独放在上传记录中，不冒充服务最终响应。失败时只输出 `CLI_PUBLISH_FAILED`、local/remote 状态和异常类型，不输出凭据、SDK 异常原文或 traceback。

## 用户后续最小配置

没有真实 COS 桶时只完成上面的实现与 mocked 测试，不创建资源。

1. 在腾讯云对象存储创建广州（`ap-guangzhou`）桶，记录完整的 `<BucketName-Appid>`。本轮不购买服务器、不改 DNS、不重新备案、不删除 GitHub Pages。
2. 对 `subtitles/evening-weather/*` 配置公开读、私有写。匿名公开读只允许 `GetObject`，不要开放列举桶、写入或删除；COS 默认私有，需要明确配置对象/文件夹/桶的公开读。
3. 给发布用 CAM 子账号/临时凭据只授予该前缀的 `PutObject`。当前发布器的验证 GET 是无鉴权公开 GET，因此写凭据不需要为验证额外授予 `GetObject`；若另行使用签名管理工具，再单独评估最小读权限。不要给本任务凭据 `*` 资源或删除/策略管理权限。
4. 在本机安全环境变量中设置上面的四个必填值；临时凭据同时设置 token。Secret 不进入聊天或客户端，客户端只会使用公开 URL。
5. 先用 `--publish-existing --publish-target cos --report-file <安全的本地报告路径>` 上传一个已经存在的 exact date，确认结构化报告中的三个公开 URL、最终响应头和 hash；再从目标网络对 index、manifest、VTT 做无鉴权 GET。真实 COS 验证完成前不要修改 `local.properties` 或 Android 主源。

6. 第一轮日期对象不可覆盖保护要求桶未启用版本控制；腾讯云文档明确说明桶开启版本控制时 `x-cos-forbid-overwrite` 会失效。若后续必须启用版本控制，应先重新设计版本/冲突语义，不得把本轮发布器当作仍具备防覆盖能力。
